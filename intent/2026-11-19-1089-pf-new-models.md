# Intent: enable the new Claude, Codex and Gemini models

## Problem

The portal model pickers and the backend shorthands still offer old models: `opus` resolves to claude-opus-4-8, `haiku` to claude-haiku-4-5, the UI maps opus to 4-7 and shows "Claude Opus 4.7 / Sonnet 4.6 / Haiku 4.5", Codex lists gpt-5.x and Gemini lists gemini-3.7/3.1. The cost catalog carries wrong prices for Opus 5.5 and Sonnet 5 and has no Fable 5.2, Sonnet 5.5 or Haiku 5.5.

## Proposed outcome

- Pickers list the new models first: Claude Fable 5.2, Opus 5.5, Sonnet 5.5, Haiku 5.5; Codex gpt-6.2-sol and the gpt-6.x family; Gemini 4 (carbon, argon, neon) and Gemini 3.8 Flash low/medium/high.
- `opus`, `sonnet`, `haiku` resolve to the 5.5 models, `fable` resolves to claude-fable-5-2; old ids remain pinnable (opus-4.8, sonnet-5, haiku-4.5, ...), so saved settings and running tasks keep working.
- Defaults that use the shorthands (all phases default to `opus`) move to Opus 5.5.
- gpt-6.* still routes to codex and gemini-4-* to gemini.
- The cost catalog has correct Claude prices and context; OpenAI and Gemini prices stay unknown.

## Affected users and systems

PFactory backend (phase_config, cost catalog, cache floors), web-server insights providers, frontend-web model constants. All portal users picking models per phase.

## Constraints

- Claude ids and prices come from the claude-api skill; no invented OpenAI or Gemini prices.
- The vendored cost_router_core.py is byte-pinned to the Factory hub: not edited (its fixture ids are test data, not a model table).
- Defaults only switch because the new ids were proven from inside the pfactory pod (Agent SDK query succeeded for opus-5-5, sonnet-5-5, haiku-5-5, including with a thinking budget).
- Historical docs, intents, specs and changelogs are not edited.

## Open questions

None (owner delegation 2026-11-19: take the recommended option; pods proof passed so defaults switch).
