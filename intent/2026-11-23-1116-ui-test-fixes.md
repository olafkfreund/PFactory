# Intent: fix the PFactory findings from the 2026-11-23 UI test

## Problem

The browser test (Factory#3873, PFactory#1116) found PFactory listing **no
projects**, so every project menu was disabled. The live registry holds one
project with no `org_id`, and the visibility filter
(`routes/project_authz.py:225-236`) drops projects without one.
`ensure_tracked_project` stamps an org only when the caller passes it.

Also found:
- the nav label "Tests" opens "PFactory Tasks";
- the empty state names the handover direction backwards;
- Settings shows "1.0.0-web";
- Add Project opens on a `/home` local folder with an error;
- the chart default keeps `~/.pfactory` on an `emptyDir`. Prod is fine:
  gitops mounts a PVC there.

## Proposed outcome

- The owner sees PFactory's projects, and new or auto-tracked projects are
  always visible to their org.
- The labels say what the page is.
- The version is right.
- Add Project opens on Git URL.
- A chart install keeps its registry across restarts.

## Affected users and systems

PFactory web server, frontend and Helm chart.

## Constraints

- D6 and P3 are unchanged: never widen visibility beyond the project's org.
- The backfill only stamps rows with no org, using the deployment's default
  org.
- Bug fixes only.

## Open questions

None.
