# Spec: enable the new models

## Design

1. `apps/backend/phase_config.py` MODEL_ID_MAP: `opus`->claude-opus-5-5, `sonnet`->claude-sonnet-5-5, `haiku`->claude-haiku-5-5, new `fable`->claude-fable-5-2. Legacy pins kept: `opus-4.8`, `opus-4.7`, `opus-1m`, `opus-4.5`, `sonnet-5`, `sonnet-4.6`, `haiku-4.5`. The env-var override map gets no `fable` entry (no documented variable). `infer_provider_from_model` already sends `claude-*`/shorthand to claude, `gpt-*` to codex, `gemini*` to gemini: no change needed, a test pins it. Default phase models stay `opus` (now Opus 5.5).
2. `apps/backend/plan/emit/model-catalog.json`: add claude-fable-5-2 (8/40), claude-sonnet-5-5 (2/10), claude-haiku-5-5 (0.10/0.50, 1M ctx); correct claude-opus-5-5 to 4/20; correct claude-sonnet-5 to 2/10 and mark it superseded (available false); claude-fable-5 kept; claude-opus-4-8 and claude-haiku-4-5-20251001 stay (haiku 4.5 marked superseded, pinnable). Codex stays subscription; the existing gemini row is left as is (no new Gemini or OpenAI price is added; none can be verified). New rows: fable-5-2 and sonnet-5-5 get roles planning/coding/qa/test_gen, haiku-5-5 gets coding/qa/test_gen like haiku 4.5; classes frontier/balanced/cheap.
3. `apps/backend/core/cache.py` `_MIN_CACHE_TOKENS`: add 512-token floors for claude-fable-5-2, claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5, 1024 for claude-opus-4-8 and claude-sonnet-5 (claude-api skill table).
4. `apps/backend/core/model_config.py` DEFAULT_UTILITY_MODEL and `core/workspace/merge.py` utility model: claude-haiku-5-5.
5. `apps/web-server/.../insights_providers/{claude,codex,gemini}_provider.py` and `apps/frontend-web/src/shared/constants/models.ts` (AVAILABLE_MODELS, ALL_AVAILABLE_MODELS, PROVIDER_MODELS, MODEL_ID_MAP): new models first; old ids stay listed after the new ones so existing selections still render. Codex default in providers/codex_agentic.py and insights codex provider becomes gpt-6.2-sol; Gemini default stays an existing id unless gemini_agentic docstring example only (docstring updated to gemini-4-carbon-medium).
6. `apps/backend/plan/usage.py` `_PRICE_PER_MTOK` (longest-prefix table): add claude-fable-5-2 (8,40), claude-opus-5-5 (4,20), claude-sonnet-5-5 (2,10), claude-sonnet-5 (2,10), claude-haiku-5-5 (0.10,0.50) so new ids no longer cost 0.
7. Claude ids in Insights and the TS PROVIDER_MODELS use the full id `claude-fable-5-2` for Fable (the claude CLI is not guaranteed to know a `fable` shorthand); phase pickers keep the shorthands and the backend resolves them. `agent_service.py` fallback check (non-Claude retry with Sonnet) treats any name starting opus/sonnet/haiku/fable as Claude so pinned aliases such as `opus-4.8` are not retried as non-Claude.
8. Codex list from `~/.codex/models_cache.json` (visible: gpt-6.2-sol, gpt-6.2-astra, gpt-6.1-terra, gpt-6.1-sol, gpt-6-astra, gpt-6-sol, gpt-6-luna, gpt-5.6-sol/terra/luna). Gemini ids from the local agy config: gemini-4-carbon-medium, gemini-4-argon-medium, gemini-4-neon-medium, gemini-3.8-flash-{high,medium,low}.

## Alternatives rejected

- Dropping the old ids: breaks saved settings and running tasks.
- Editing cost_router_core.py: byte-pinned to the hub; fixture only.
- Guessing OpenAI/Gemini prices: unverifiable; the catalog keeps subscription/unknown.

## Risks

- Shorthands are re-resolved per phase, so saved `opus`/`sonnet`/`haiku` follow the new models on the next phase of a running task; settings that stored full ids (e.g. claude-opus-4-8) stay. Rolling back removes the new aliases (opus-4.8, sonnet-5, haiku-4.5) only if they were saved under those spellings; the old three shorthands keep working. The default `opus` is the backend fallback; the frontend Auto profile keeps its own per-phase choices.
- Gemini-4 ids come from local agy; the shipped image installs gemini-cli as `antigravity`, so they are listed (owner request) but the backend fallback model is unchanged and no phase defaults to them. Not verified in the image.
- Routing: the cost router picks the cheapest available balanced/cheap Claude, so it now picks sonnet-5-5 and haiku-5-5; tests pinning old picks are updated.
- Thinking: legacy `max_thinking_tokens` path is kept; proven working in the pod on opus-5-5 and haiku-5-5.
- gemini-4-* ids are taken from local agy logs, not an API list; wrong spelling would fail at run time but cannot affect Claude phases.
