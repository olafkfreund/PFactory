# Spec: PFactory UI test fixes

## Design

- **B2a.** At the intake boundary, the org that was authorized is the org
  that gets persisted:
  - `ingest_text` (`plan_pipeline.py:307-329`) and `ingest_upload`
    (`:492-512`) pass the `_ingest_org(...)` result to
    `ensure_tracked_project` instead of re-calling `creator_org`;
  - the issue paths (`:393,462`) already do;
  - a service principal's literal `"default"` is resolved through a new
    async `resolve_default_org_id(db)`, which returns the sole
    `Organization.id` when exactly one org exists and `None` otherwise.

  `ensure_tracked_project` keeps the existing ownership of a repo it
  reuses, and never invents an org: `None` stays unstamped, and the test
  `test_unstamped_project_is_404_for_non_service` is kept. The legacy MCP
  project-create route (`mcp_stdio/router.py:327`) uses the same resolver.
- **B2b.** A one-time **async startup backfill** runs in the `main.py`
  lifespan after `init_db()`:
  - if exactly one `Organization` row exists, org-less projects are stamped
    with that `id`;
  - otherwise nothing is stamped and each org-less project is logged as
    unassigned;
  - it runs under a file lock, with an atomic write (temp file and
    `os.replace`), and is idempotent;
  - every stamp is logged with the project id, so a mistaken stamp can be
    identified and reversed.
- **B2c.** `charts/pfactory`:
  - `values.yaml` gains
    `persistence.data: {enabled: false, existingClaim: "", size: 1Gi, storageClass: "", accessMode: ReadWriteOnce}`;
  - a new `templates/data-pvc.yaml` is created when enabled and no
    `existingClaim` is set;
  - the `pfactory-data` volume (`deployment.yaml:368-369`) uses the claim
    when enabled, else `emptyDir`;
  - the volume name is unchanged;
  - a values comment explains copying the registry before switching an
    existing install.
- **B4.** `api-adapter.ts:673` (`getAppVersion`) and `:940-945`
  (`getDebugInfo`) use one shared lookup of `/api/health`. A failure gives
  "unknown" and is retried on the next call.
- **B9.** The `pfactory` view lists test workspaces from AIFactory
  handovers, so the "Tests" label and the empty-state copy are correct. The
  page title (`PFactoryPortal.tsx:34`) becomes "Test runs", with
  "Back to test runs" and "Loading test runs…". `items.tests` is added to
  `pt-BR/navigation.json`. Update `PFactoryPortal.test.tsx:79` and
  `PFactoryTaskList.test.tsx:95`. Do not rename to "Plans", which would
  clash with `items.plans`.
- **B10.** `AddProjectModal.tsx`:
  - `:54` and `:109` default and reset to `clone`;
  - `:113` scan removed from the open effect, with `scanProjects` dropped
    from the deps at `:115`;
  - the Local Search button and Enter behaviour are kept;
  - the `DialogDescription` at `:210-212` is mode-aware.

## Alternatives rejected

- **Lowering the visibility filter to show org-less projects:** that is an
  existence or visibility leak across orgs.
- **Backfilling inside `load_projects`:** it is synchronous with no database
  access and is called from authorization; a whole-file write there races
  across up to four replicas.

## Risks

- B2b must not stamp in a multi-org deployment where the owner org is
  ambiguous.

## Verification

- Unit tests:
  - `ensure_tracked_project` stamps an org;
  - load backfills a single-org registry;
  - the multi-org case is not guessed;
  - the visibility filter shows the stamped project to org members and not
    to other orgs.
- vitest for B4, B9 and B10.
- `helm template` with and without persistence.
- CI.
- After release, a browser check: PFactory lists the project and the
  menus are enabled.
