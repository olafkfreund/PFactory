# Plan: running work is visible, guarded and stoppable from any replica

Self-contained summary of the approved decisions:

- **Table:** `run_leases` holds one row per running thing. The migration's
  `down_revision` is `f2c7a9d4e1b3`. Columns:
  - `kind` `String(32)` and `key` `String(255)`, together the primary key;
  - `owner` `String(128)`, set to `hostname:pid`;
  - `lease_until` `DateTime(timezone=True)`, on the database clock;
  - `stop_requested` `Boolean`, default false.
- **Helper:** `server/services/run_leases.py`. Every call is async, uses
  `async_session_factory`, and takes its times from the database (#758
  `_now_and_until`).
  - `acquire(kind, key, *, steal=False)`, `release`, `is_active`,
    `active_keys(kind)`, `request_stop`, `stop_and_wait(kind, key, timeout)`.
  - `watch(kind, key, *, alive, stop)`: a 1 s tick. It releases when
    `alive()` turns false. Every heartbeat it renews with `UPDATE ... WHERE
    owner = me RETURNING stop_requested`:
    - no row → `stop()`;
    - `stop_requested` → `stop()`, then release once the run is dead;
    - a DB error → ERROR log, keep running.
  - Configuration: `PFACTORY_RUN_LEASE_TTL_SECONDS` (60) and
    `PFACTORY_RUN_LEASE_HEARTBEAT_SECONDS` (15). Invalid means the default,
    and the heartbeat is capped at TTL / 3.
- **Services:** each acquires before registering its run, calls `watch`
  after, and releases if spawning fails.
  - Agent tasks: `task`, keyed by `project_id:spec_id`; `stop_task`.
  - PR review: `pr_review`, keyed by `project_id:pr`; `cancel_review`.
  - Changelog: `changelog`, keyed by `project_id`; `stop_generation`.
  - Insights: `insights`, keyed by `project_id`, acquired with `steal=True`;
    `stop_message`. `start_message` becomes async.
  - Each service gains an async `is_running_anywhere`. The sync `is_running`
    stays local.
- **Routes:**
  - status and running lists read `is_running_anywhere` and `active_keys`;
  - the start and review guards return 409 across pods, and the changelog
    guard returns "already in progress";
  - a stop or cancel for a remote run calls `request_stop` and returns
    "requested";
  - recover and the force paths (the start with `force_execution`, the
    approve-plan restart at `tasks.py:1650`) call `stop_and_wait`, and
    return 409 if the lease is still held.
- **Rejected:** `job_states`, forwarding stops over HTTP, per-site release
  calls, session affinity, making `is_running` async everywhere.

### Details found while planning (within the spec's design)

1. **A same-pod restart.** The force path calls `stop_task`, which removes
   the local entry, and then restarts at once, before the watcher's next
   tick has released the old lease. `acquire` therefore also succeeds when
   the lease is **held by this owner**: `ON CONFLICT ... WHERE lease_until <
   now() OR owner = :me`. A real duplicate on the same pod is still blocked
   first by each service's existing local-dict guard (`agent_service.py:537`,
   `:756`, and its peers).
2. **One watcher per key per pod.** `watch` keeps a module-level
   `{(kind, key): asyncio.Task}`, and does nothing while a live watcher for
   that key exists. Otherwise a same-pod restart would leave two loops
   renewing one lease.
3. **The lease refusal must be a 409, not a 500.** The routes await the
   service's start, and `routes/execution.py:514` maps any exception to 500.
   The services raise `RunAlreadyActiveError(ValueError)`, defined in
   `run_leases.py`, when `acquire` fails. `execution.py` (both start paths),
   `tasks.py` and the PR-review route catch it and return 409. The changelog
   route returns its existing "already in progress". The acquire sits in the
   service, so every caller is covered, including the in-process
   `mcp_stdio` proxy.

All work happens in the worktree `/tmp/.../scratchpad/pf-805` on
`fix/805-run-leases`, with the backend `.venv` symlinked in and never
staged. Postgres runs use a dedicated pg16 container with a `pfactory_test`
database, stopped afterwards.

## Steps

1. **Tests first.** In the web-server tests, SQLite `create_all` with a
   patched `async_session_factory`, a patched `OWNER` for a second pod, and
   env TTL=3 and heartbeat=1 for speed:
   - a new `test_run_leases.py`, covering:
     - exclusive acquire;
     - acquiring after expiry;
     - re-acquire by the same owner;
     - steal;
     - release only by the owner;
     - `request_stop` → `watch` calls `stop`;
     - a stolen lease → `stop`;
     - `alive()` false → the row is released;
     - a DB error in the heartbeat → no `stop`;
     - one watcher per key;
   - a new `test_run_leases_routes.py`, with the lease held by the other
     owner. It covers:
     - `/api/tasks/running` lists the task, and `/status` and `/running`

     - stop returns "requested" and sets the flag;
     - recover returns 409 while held;
     - PR review start returns 409 and cancel returns "requested";
     - the changelog generate guard refuses;
     - the insights stop request.

## Rollback

- Revert the fix commit and release a patch. The old code ignores
  `run_leases`, so the table can stay; `alembic downgrade -1` drops it.
- During a rollback deploy, runs started by the new code keep their rows
  until the rows expire (60 s), and nothing reads them.
