# Plan: Three planning components are still hardcoded English

Approved decisions (from the spec):

- One `common.json` namespace per component: `pipelinePanel`,
  `enrichmentPanel`, `planUploadForm`; `useTranslation('common')`.
- Every user-facing string behind a key, incl. `aria-label`, `placeholder`,
  empty-state prose; `{{count}}`-style interpolation, no concatenation.
- `PipelinePanel`'s module-level `KIND_META` holds `labelKey`; the component
  resolves it. Its unknown-kind fallback keeps the RAW kind string (data).
- Badge identifiers (`adr`, `doc`, `policy`, `best-practice`, `catalog`,
  `template`) stay untranslated (intent Q1).
- Real `fr` / `pt-BR` translations, matching the register of existing entries.
- `planning-locale-parity.test.ts` `NAMESPACES` → six entries, adding the
  pre-existing gap `approval`.
- `PlanUploadForm.test.tsx` adopts `__tests__/i18n-mock.ts`.
